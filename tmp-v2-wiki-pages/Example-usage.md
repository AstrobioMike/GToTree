# *Alteromonas* example
Here we imagine we have a newly recovered genome of interest and we want to see where it fits into its evolutionary landscape alongside its closest known relatives.

## The setup
During my PhD I had the privilege of working on a really cool, nitrogen-fixing, marine cyanobacterium called *Trichodesmium*. This bug seems to only live in perpetual association with a consortium of other microorganisms – there are no pure (axenic) cultures of *Trichodesmium* by itself, it just doesn't seem to be happy without its buddies. One of the highly conserved organisms (here meaning consistently present across all *Trichodesmium* samples, but not in non-*Trichodesmium* "controls") that came out of this work was an *Alteromonas* **m**etagenome-**a**ssembled **g**enome (MAG) – some of that fun work is presented in [this paper here](https://www.nature.com/articles/ismej201749). 

**Here we are going to use GToTree to generate a de novo phylogenomic tree with this "new" *Alteromonas* MAG placed among *Alteromonas* reference genomes.**

## Generating inputs
### Genomes
The inputs for this example will be: 1) the fasta file of our "new" MAG; 2) *Alteromonas* reference genomes; and 3) an alphaproteobacterium to serve as a root.

**1)** We can download the MAG fasta file from NCBI and decompress it like such:

```bash
curl -L https://ftp.ncbi.nlm.nih.gov/genomes/all/GCA/002/271/865/GCA_002271865.1_ASM227186v1/GCA_002271865.1_ASM227186v1_genomic.fna.gz | gunzip - > GCA_002271865.1.fa
```

<a id="accessions"></a>
**2)** For the reference genomes, v2 makes this a lot easier than it used to be — we can just name the taxon we want with `-w` and GToTree will gather them (see the [next example](example-usage#building-a-tree-from-a-taxon-name) for more on this). We'll do that below.

If you'd rather assemble an accessions list yourself — for instance to hand-pick which genomes go in — you can still do that and pass it to `-a`. Two ways:

* Search [NCBI's assembly database](https://www.ncbi.nlm.nih.gov/datasets/genome/) on their website and download a summary file, then pull out the accession column.
* Or use the packaged helpers, `gtt get-accs-from-ncbi` and `gtt get-accs-from-gtdb`.

**3)** And to have an outgroup to root the tree with, and to incorporate a GenBank file which GToTree can handle as input as well, we'll take an alphaproteobacterium:

```bash
curl -L https://ftp.ncbi.nlm.nih.gov/genomes/all/GCF/000/011/365/GCF_000011365.1_ASM1136v1/GCF_000011365.1_ASM1136v1_genomic.gbff.gz | gunzip - > GCF_000011365.1.gbff
```

### Mapping file for labeling specific genomes
Often it is helpful to have specific labels for specific genomes in a tree. In this case we may want to have our "new" MAG labeled as "Our_Alteromonas_MAG", instead of just "GCA_002271865.1", and we may want to label our root as "Alpha_root" instead of "GCF_000011365.1". GToTree can add lineage information to any genomes that have such information associated with them, but we can also swap labels of specific genomes we know we care about and want to be able to find more easily.

To do that we just need to provide a 2-column, tab-delimited file that has the initial genome ID in the first column (this will be either the NCBI accession or the file name, depending on how the genome was provided). This can be made anywhere, but here is quickly making one for this example: 

```bash
printf "GCA_002271865.1.fa\tOur_Alteromonas_MAG\nGCF_000011365.1.gbff\tGCF_000011365.1_Alpha_Outgroup\n" > genome-to-id-map.tsv
```

Which looks like this:

```bash
cat genome-to-id-map.tsv
```
```
GCA_002271865.1.fa	Our_Alteromonas_MAG
GCF_000011365.1.gbff	GCF_000011365.1_Alpha_Outgroup
```
---
> **NOTE:** User-provided labels given to genomes listed in this mapping file (passed to the program with the `-m` flag) will always take precedence over any automated lineage swapping.

## Running GToTree
To tell GToTree which fasta and genbank files to work on, we need to put their names (or [paths](https://astrobiomike.github.io/unix/getting-started#the-unix-file-system-structure)) into files. In the case here, this will get the job done:

```bash
ls *.fa > fasta-files.txt
ls *.gbff > genbank-files.txt
```

Now we are set to run GToTree :)

> **Note:** If you're not familiar with seeing things like the codeblock just below, you can ignore the backslashes (`\`) in here. They are only there to ["escape"](https://en.wikipedia.org/wiki/Backslash) the return characters so this can all be seen at once (instead of one long line you'd have to scroll), and so it can be copy-and-pasted if wanted 😊

```bash
gtotree -w Alteromonas -g genbank-files.txt \
        -f fasta-files.txt \
        -D -L genus,species -m genome-to-id-map.tsv -j 4 \
        -o alteromonas-example
```

> **Code Breakdown:**
>  * **-w** – the taxon whose reference genomes to gather and include  
>  * **-g** – the file holding the genbank paths  
>  * **-f** – the file holding the fasta paths  
>  * **-D** – add GTDB lineage information to the tree labels  
>  * **-L** – the ranks to add when adding lineage information; since we're working within *Alteromonas*, genus and species are plenty  
>  * **-m** – the mapping file specifying specific labels for specific input genomes  
>  * **-j** – the number of jobs to run in parallel when possible  
>  * **-o** – the output directory  

Note there's no `-H` here. Because we used `-w`, GToTree picks an appropriate SCG-set for us — *Alteromonas* sits within Gammaproteobacteria in GTDB, so that's the set it will choose. It tells us which one it picked, and why, in the banner at the start of the run. If we wanted to force a specific one, we'd add e.g. `-H Gammaproteobacteria`.

## Viewing/Editing the tree
The output tree file is named after the output directory, so here it's `alteromonas-example/alteromonas-example.tre`. It's in newick format and can be viewed/edited with any general tree program. A good one for large trees that I have installed on my laptop and use regularly is [Dendroscope](http://dendroscope.org/). And a good web-based one is the [Interactive Tree of Life](https://itol.embl.de/). 

GToTree midpoint-roots the output tree for you (the un-rooted version is kept in `run-files/` if you want it). # Building a tree from a taxon name

New in v2. Rather than gathering accessions first, we can name the taxon we want and let GToTree do it:

```bash
gtotree -w Nitrospirota -D -j 4 -o nitrospirota-tree
```

That gathers the *Nitrospirota* reference genomes, picks a covering SCG-set (there's a packaged *Nitrospirota* set, so it'll use that), builds the tree, and adds GTDB taxonomy to the labels.

A few things worth knowing:

**Where the genomes come from.** `--source` chooses the taxonomy the genomes are drawn from, `gtdb` (default) or `ncbi`.

**Controlling how many genomes you get.** By default `--derep-rank auto` dereplicates down to two ranks finer than your target, which keeps the tree a manageable size for broad taxa. You can set it explicitly, or turn it off:

```bash
  # one genome per family within the phylum
gtotree -w Nitrospirota --derep-rank family -o nitrospirota-by-family

  # every genome under the taxon
gtotree -w Nitrospirota --derep-rank off -o nitrospirota-all
```

**Combining taxa.** `-w` can be given more than once, and each taxon is resolved and dereplicated on its own before they're merged:

```bash
gtotree -w Nitrospirota -w Nitrospinota -D -j 4 -o nitrospir-tree
```

When several taxa are given and no `-H`, GToTree picks the lowest-rank packaged set that covers all of them — here both are bacterial phyla, so it'd use the `Bacteria` set. Give it `-w Bacteria -w Archaea` and it'd use `Bacteria-and-Archaea`.

**Mixing with your own genomes.** This composes with all the other input types, which is the usual real-world case — some new MAGs of your own, placed among references:

```bash
gtotree -w Nitrospirota -f my-mag-files.txt -D -j 4 -o my-mags-in-context
```

**Ambiguous names.** If a name exists at more than one rank, GToTree will stop and ask you to disambiguate with `--target-rank`.

# Using GToTree with the Genome Taxonomy Database (GTDB)
There are a few ways we can use the stellar [GTDB](https://gtdb.ecogenomic.org/) with GToTree:

1. We can add GTDB taxonomy to our tree labels instead of NCBI taxonomy. This is done by adding the `-D` flag in the main GToTree call.
2. We can gather reference genomes by GTDB taxonomy directly in the main call with `-w` (GTDB is the default `--source`), as shown in the [example above](example-usage#building-a-tree-from-a-taxon-name).
3. We can do a standalone search by GTDB taxonomy to gather accessions, with `gtt get-accs-from-gtdb`. This is useful when you want the accession list itself, or want to inspect/subset it before running.

**For example**, say we have a few new **m**etagenome-**a**ssembled **g**enomes (MAGs) that we just classified with the wonderful [gtdb-tk](https://github.com/Ecogenomics/GTDBTk#gtdb-tk) program as part of the Nitrososphaerales order. If we'd now like to make a de novo phylogenomic tree with our new MAGs placed within the context of all the Nitrososphaerales in the GTDB, we can search GTDB based on taxonomy:

This will report how many Nitrososphaerales there are in the GTDB:

```bash
gtt get-accs-from-gtdb -t Nitrososphaerales --get-taxon-counts
```


That writes `gtdb-nitrososphaerales-order-gtdb-rep-accs.txt` and a matching `-metadata.tsv`. (Output names are lowercased in v2, where v1 wrote e.g. `GTDB-Nitrososphaerales-order-GTDB-rep-accs.txt`.)

Then we are ready to provide those accessions to GToTree as usual to build a de novo tree with our new MAGs:

```bash
gtotree -f our-MAG-fasta-files.txt -a gtdb-nitrososphaerales-order-gtdb-rep-accs.txt \
        -H Archaea -D -j 4 -o nitrososphaerales-tree
```

Where the **`-D`** flag will also swap out the input accessions for their GTDB taxonomy on the final tree 😊

> Note that for this particular case we could skip the two-step entirely and just run `gtotree -f our-MAG-fasta-files.txt -w Nitrososphaerales -D -j 4 -o nitrososphaerales-tree`. The standalone helper is there for when you want the accession list in hand.

### Random notes on `gtt get-accs-from-gtdb`
For other usage info, see `gtt get-accs-from-gtdb -h`. Like if we wanted all genomes, we could provide "all" to the `-t` target taxon argument. `--derep-rank` will dereplicate the pulled genomes down to one per unique value of a rank, and `-R`/`--refseq-reference-genomes-only` restricts to RefSeq reference genomes. `--get-rank-counts` on its own shows how many unique taxa there are at each rank.

And if we wanted to just download the genomes, rather than use them with GToTree, we could get the accessions as shown above, and then use `bit-dl-ncbi-assemblies` from the [bit](https://github.com/AstrobioMike/bit) package, e.g.:

```bash
  # search GTDB based on taxonomy to get corresponding NCBI accessions
gtt get-accs-from-gtdb -t Nitrososphaerales -G

  # download accessions in fasta format 
bit-dl-ncbi-assemblies -w gtdb-nitrososphaerales-order-gtdb-rep-accs.txt -f fasta -j 4
```

## The setup
Depending on the scope of the question being pursued, it can sometimes be useful to visualize a trait or characteristic across an entire domain or large clade, as this may reveal patterns about its evolutionary distribution. The presence or absence of a particular trait in a given genome can be acquired in any fashion – e.g., using annotations already available, using a program to identify a specific antibiotic resistance marker if that's your thing, or searching for genes of interest based on hidden Markov Models (HMMs). GToTree already uses these to find single-copy genes, and also supports searching for any additional target [Pfam](https://www.ebi.ac.uk/interpro/entry/pfam/) accessions or [KEGG KO](https://www.genome.jp/kegg/ko.html) IDs. While processing the genomes to find single-copy genes for building the tree, if provided a file of additional Pfam targets, GToTree will also search for these in each genome and: 1) pull out and store the hit sequences; 2) generate a count table of hits per genome; and 3) generate an [Interactive Tree of Life](https://itol.embl.de/)-compatible file for each target so all can be easily visualized at their [upload site](https://itol.embl.de/upload.cgi)!

Here we will demonstrate this searching for the presence of flagellar protein FliT ([PF05400](https://www.ebi.ac.uk/interpro/entry/pfam/PF05400/)) across the bacterial domain.

>Note: This is not a particularly quick example because it is done at a large scale, so while it may not be great for following along executing the code, it shows the process. Things can be done the same way on any smaller subset of organisms with any Pfam targets (or with any other metric for a characteristic, as discussed below).

## Getting the genomes
In v1 this step meant assembling a large accessions list first. In v2 we can ask for the domain directly and let dereplication keep it to a workable size:

```bash
gtotree -w Bacteria --derep-rank family -H Bacteria -p pfam-targets.txt \
        -D -j 50 -o flit-bacterial-tree
```

`--derep-rank family` keeps one genome per bacterial family. Adjust that coarser or finer depending on how dense you want the tree — `--derep-rank order` for something smaller, `class` smaller still.

For this example we're just looking for the flagellar protein FliT ([PF05400](https://www.ebi.ac.uk/interpro/entry/pfam/PF05400/)), but we could search for as many as we'd like. So for good measure let's add another one to the list, a ribosomal protein ([PF00238](https://www.ebi.ac.uk/interpro/entry/pfam/PF00238/)). Here's just throwing them into a file:

```bash

```

# Using the alignment and partitions file with another program
Some tree-building programs allow for the incorporation of mixed models – meaning they will treat each gene differently rather than all the same. GToTree generates a partitions file that is compatible with most of these. If you wanted to do this, you might want to run GToTree in alignment-only mode (by adding the `-N` flag when running), and then take the alignment and partitions file into a stellar program like [iqtree](http://www.iqtree.org/) – which has [excellent documentation here](http://www.iqtree.org/doc/Home#documentation). While [iqtree](http://www.iqtree.org/) is installed with GToTree by default, running it within GToTree is doing things in a very standard, generic way. As discussed on the [Things to Consider page](https://github.com/AstrobioMike/GToTree/wiki/things-to-consider#an-important-caveat-on-the-idea-of-a-workflow-for-phylogenomics), you have to sacrifice some level of control as you broaden out to an entire workflow. So GToTree gives you the alignment and partitions file so if you'd like you can take them into something like [iqtree](http://www.iqtree.org/) and take advantage of all their functionality. If you're looking specifically for their information on mixed-model analysis, a good place to start is their [advanced documentation here](http://www.iqtree.org/doc/Advanced-Tutorial#partitioned-analysis-for-multi-gene-alignments).

Here is an example of one way you might do this with [iqtree](http://www.iqtree.org/) using the alignment and partitions outputs from the [*Alteromonas* example above](https://github.com/AstrobioMike/GToTree/wiki/example-usage#alteromonas-example). 

```bash
iqtree -s alteromonas-example/aligned-SCGs-mod-names.faa \
       -spp alteromonas-example/run-files/partitions.txt \
       -m MFP -bb 1000 -nt 4 -pre iqtree-out
```

> **Code Breakdown:**
>  * **-s** – the alignment file we got from GToTree  
>  * **-spp** – the partitions file we got from GToTree  
>    * note that sometimes the txt-formatted partitions file [won't work with iqtree](https://github.com/AstrobioMike/GToTree/issues/108), but you can use the nex-formatted file (`partitions.nex`) that is produced in the same location  
>  * **-m** – telling iqtree to use model finder plus to select the model  
>  * **-bb** – number of ["ultrafast" bootstraps](http://www.iqtree.org/doc/Tutorial#assessing-branch-supports-with-ultrafast-bootstrap-approximation) we want  
>  * **-nt** – number of threads we want to use  
>  * **-pre** – the prefix of the output files generated  

> If the run added taxonomy or used a mapping file, the alignment with the nicer labels is `aligned-SCGs-mod-names.faa`; otherwise use `aligned-SCGs.faa`.

# ToL Example
Here we generate a 3-domain tree like the one in the [original GToTree paper](https://doi.org/10.1093/bioinformatics/btz188).

In v2 this is close a one-liner, since we can ask for all domains directly:

```bash
gtotree -w Bacteria -w Archaea -w Eukarya --source ncbi --derep-rank order --add-ncbi-tax -j 10 -G 0.4
```

> **Code Breakdown:**
>  * **-w Bacteria -w Archaea -w Eukarya** – all domains; each is gathered and dereplicated separately, then merged  
>  * **--source ncbi** - setting NCBI as the source of genomes since we want to include eukaryotes
>  * **--derep-rank order** – subset to one genome per order, to keep the tree a reasonable size that still shows the breadth of diversity we care about
>  * **--add-ncbi-tax** – add NCBI lineage info to the labels
>  * **-j 10** - set up to 10 jobs to run in parallel where possible
>  * **-G 0.4** – relax the genome-hits cutoff, so more genomes make it through to the final tree at this broad level of diversity

No `-H` needed: with `-w Bacteria -w Archaea -w Eukarya` spanning all 3 domains, GToTree auto-selects the `Universal` SCG-set, which is built for exactly this case.
